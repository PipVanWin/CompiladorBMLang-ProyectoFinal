# 1. Requerimientos del sistema

Para el desarrollo del entorno de desarrollo integrado BMLang IDE se utilizaron tecnologías de desarrollo web que permiten la interacción entre el usuario, el compilador y los diferentes módulos del sistema.

## 1.1. Requerimientos de JavaScript

JavaScript se utiliza para implementar la interactividad del entorno de desarrollo integrado (IDE), permitiendo que el usuario pueda escribir código, utilizar las herramientas disponibles y visualizar los resultados del compilador.

Los requerimientos implementados son:

- Permitir la interacción con el editor de código fuente.
- Actualizar dinámicamente los números de línea y las estadísticas del editor.
- Permitir crear, abrir y guardar archivos con extensión `.bml`.
- Incorporar ejemplos de código para facilitar las pruebas del lenguaje.
- Implementar un sistema de pestañas para visualizar los resultados.
- Permitir la comunicación con el backend mediante solicitudes HTTP.
- Mostrar los resultados de los procesos de compilación.
- Visualizar los tokens generados por el analizador léxico.
- Mostrar el árbol de sintaxis abstracta (AST).
- Permitir visualizar el código de tres direcciones (C3D).
- Permitir visualizar el código ensamblador NASM.
- Incorporar una consola para mostrar mensajes, errores y resultados.
- Implementar funciones para copiar resultados al portapapeles.
- Permitir la ejecución y depuración paso a paso mediante una máquina virtual experimental.

## 1.2. Requerimientos de Node.js

Node.js se utiliza como entorno de ejecución del backend, permitiendo ejecutar JavaScript del lado del servidor y gestionar las operaciones relacionadas con el compilador.

Los requerimientos implementados son:

- Ejecutar el servidor backend de la aplicación.
- Gestionar las solicitudes provenientes del frontend.
- Procesar el código fuente enviado desde el editor.
- Ejecutar el compilador desarrollado con Flex y Bison.
- Gestionar los procesos externos necesarios para generar los resultados de compilación.
- Capturar las salidas y errores producidos por el compilador.
- Gestionar la generación y descarga de archivos ejecutables.
- Permitir la ejecución del programa compilado mediante el backend.

## 1.3. Requerimientos de Express.js

Express.js se utiliza como framework para desarrollar la API REST que permite la comunicación entre el frontend y el backend.

Los requerimientos implementados son:

- Crear un servidor HTTP para atender las solicitudes del IDE.
- Definir rutas para las diferentes operaciones del compilador.
- Implementar el endpoint `/api/compile` para solicitar procesos de compilación.
- Implementar el endpoint `/api/build` para generar y descargar ejecutables.
- Implementar el endpoint `/api/run` para compilar y ejecutar programas.
- Recibir información mediante solicitudes POST.
- Procesar datos enviados en formato JSON.
- Habilitar la comunicación entre el frontend y el backend mediante CORS.
- Devolver respuestas JSON con los resultados de las operaciones y los errores correspondientes.

# 2. Explicación de lo desarrollado

## 2.1. JavaScript

JavaScript es el lenguaje utilizado para desarrollar la lógica del frontend de BMLang IDE. Su función principal es conectar los elementos visuales de la interfaz con las operaciones que realiza el compilador.

Se desarrollaron diferentes funciones para administrar el editor y sus herramientas.

### Administración del editor

Se implementaron funciones que permiten trabajar con el código fuente:

- `newFile()`: permite crear un archivo nuevo y limpiar el contenido del editor.
- `openFile()`: permite seleccionar y cargar archivos `.bml` o `.txt`.
- `saveFile()`: permite descargar el código fuente como un archivo.
- `updateEditorStats()`: actualiza la cantidad de líneas y caracteres.
- `actualizarNumerosLinea()`: genera los números de línea del editor.
- `loadSampleCode()`: permite cargar ejemplos de programas BMLang.

Estas funcionalidades facilitan la escritura y administración de programas desde el IDE.

### Administración de pestañas

Se desarrolló la función `switchTab()`, encargada de controlar las diferentes secciones de resultados del entorno.

Esta función permite alternar entre las vistas de:

- Código de tres direcciones.
- Código NASM.
- Analizador léxico.
- Árbol de sintaxis abstracta.
- Consola de resultados.

De esta manera, el usuario puede consultar los resultados de cada proceso sin abandonar el entorno de desarrollo.

### Comunicación con el backend

Se implementó la función asíncrona `compilarEnBackend()`, que utiliza `fetch()` para enviar el código fuente al servidor mediante solicitudes HTTP.

La función envía dos datos principales:

- `code`: contiene el código fuente escrito por el usuario.
- `mode`: especifica el tipo de operación que se desea realizar.

El modo permite solicitar diferentes resultados al compilador, como el AST, el código de tres direcciones o el código NASM.

Posteriormente, JavaScript recibe la respuesta del backend y actualiza la interfaz con el resultado obtenido.

### Generación de resultados

Se desarrollaron las siguientes funciones:

- `generarAST()`: solicita al backend la generación del árbol de sintaxis abstracta.
- `compilePipeline()`: administra los procesos de generación de C3D, NASM, ejecución y construcción del ejecutable.
- `mostrarTokens()`: presenta los tokens en una tabla dentro del IDE.
- `analizarLexico()`: contiene una implementación preliminar en JavaScript para reconocer tokens y visualizar su clasificación.

El analizador léxico principal del proyecto se encuentra implementado en Flex; la función JavaScript es una herramienta complementaria.

### Consola de resultados

Se implementó `logConsole()`, que permite mostrar mensajes informativos, advertencias, errores y confirmaciones dentro del IDE.

También se desarrolló `clearConsole()`, que permite limpiar la consola cuando sea necesario.

Esto facilita la identificación de problemas y permite al usuario conocer el estado de las operaciones realizadas.

### Máquina virtual experimental

Se desarrolló una máquina virtual básica en JavaScript para interpretar instrucciones del código de tres direcciones.

Entre sus funciones principales se encuentran:

- `prepararVM()`: prepara las instrucciones para su ejecución.
- `ejecutarInstruccion()`: procesa una instrucción individual.
- `evaluarExpresion()`: evalúa operaciones aritméticas y variables.
- `stepInterpreter()`: ejecuta una instrucción a la vez.
- `runInterpreter()`: ejecuta las instrucciones disponibles.
- `actualizarVM()`: actualiza la visualización de variables, pila, contador de programa y salida.
- `finalizarVM()`: establece el estado final de la ejecución.

Esta máquina virtual es una implementación experimental complementaria y no sustituye la ejecución real del programa compilado.

## 2.2. Node.js

Node.js permite ejecutar el código JavaScript del lado del servidor. En BMLang IDE se utiliza para gestionar los procesos necesarios para comunicarse con el compilador desarrollado en C, Flex y Bison.

El backend utiliza Node.js para:

1. Recibir las solicitudes provenientes del frontend.
2. Obtener el código fuente enviado por el usuario.
3. Preparar los archivos y argumentos necesarios para ejecutar el compilador.
4. Ejecutar el compilador mediante procesos del sistema operativo.
5. Capturar la salida estándar y los errores.
6. Devolver los resultados al frontend.
7. Gestionar la generación de archivos ejecutables.

Para realizar estas operaciones se utilizan módulos de Node.js como:

- `child_process`: permite ejecutar programas y procesos externos, como el compilador.
- `fs/promises`: permite realizar operaciones con archivos de manera asíncrona.
- `path`: facilita la administración de rutas y directorios.
- `util`: permite convertir funciones basadas en callbacks en funciones compatibles con promesas.

Estos módulos permiten conectar el compilador tradicional con una interfaz web.

## 2.3. Express.js

Express.js es el framework utilizado para organizar y gestionar las rutas del backend.

Se implementó una API REST que recibe las solicitudes del frontend y ejecuta las operaciones correspondientes.

### Endpoint POST `/api/compile`

Este endpoint permite solicitar la compilación del código fuente.

Recibe una solicitud JSON con la siguiente estructura:

```json
{
    "code": "MAIN { DEC $a; $a => 10; WRITE $a; }",
    "mode": "tac"
}
```

El campo `code` contiene el programa BMLang y `mode` indica el resultado que se desea generar.

Los modos utilizados son:

- `ast`: genera el árbol de sintaxis abstracta.
- `tac`: genera el código de tres direcciones.
- `nasm`: genera el código ensamblador.

El backend ejecuta el compilador y devuelve el resultado correspondiente.

### Endpoint POST `/api/build`

Este endpoint permite generar un archivo ejecutable a partir del código fuente.

El proceso consiste en:

1. Recibir el código fuente.
2. Ejecutar el compilador para generar el código NASM.
3. Utilizar NASM para ensamblar el código.
4. Utilizar el enlazador para generar el ejecutable.
5. Enviar el archivo generado al frontend para su descarga.

De esta manera, el usuario puede obtener un programa ejecutable sin realizar manualmente todos los pasos de compilación.

### Endpoint POST `/api/run`

Este endpoint permite compilar y ejecutar un programa BMLang desde el IDE.

El backend recibe el código fuente, realiza el proceso de compilación y ejecuta el programa generado.

Posteriormente, devuelve información sobre:

- El resultado de la ejecución.
- La salida producida por el programa.
- Los errores que puedan ocurrir durante el proceso.

### Comunicación mediante JSON

Express.js permite recibir y procesar información en formato JSON mediante el middleware correspondiente.

Además, se utiliza CORS para permitir que el frontend pueda comunicarse con el servidor backend.

# 3. Integración de las tecnologías

Las tres tecnologías trabajan conjuntamente para permitir el funcionamiento de BMLang IDE.

El proceso general de comunicación es el siguiente:

1. El usuario escribe un programa en el editor desarrollado con HTML, CSS y JavaScript.
2. JavaScript captura el código fuente.
3. JavaScript envía una solicitud HTTP al backend mediante `fetch()`.
4. Express.js recibe la solicitud y procesa los datos.
5. Node.js ejecuta el compilador desarrollado con Flex, Bison y C.
6. El compilador realiza el análisis correspondiente y genera el resultado solicitado.
7. Node.js captura la salida del compilador.
8. Express.js devuelve la respuesta al frontend.
9. JavaScript recibe la respuesta y actualiza la interfaz para mostrar los resultados.

# 4. Resultado obtenido

La integración de JavaScript, Node.js y Express.js permitió desarrollar un entorno de desarrollo integrado para BMLang, en el cual el usuario puede escribir programas, administrar archivos, solicitar diferentes procesos de compilación y visualizar los resultados directamente desde una interfaz web.

JavaScript se encarga de la interacción con el usuario, Node.js administra la ejecución de los procesos del sistema y Express.js proporciona las rutas de comunicación entre el frontend y el backend.

Con esta integración se logró conectar el compilador desarrollado con Flex, Bison y C con una aplicación web, facilitando su utilización y visualización de resultados.
